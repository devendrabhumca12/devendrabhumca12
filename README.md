<sub>Engineering philosophy, in four habits</sub>

**Flagship Case Study — FormEasy**  &nbsp; [View on GitHub →](https://github.com/devendrabhumca12/FormEasy)
<br/><sub><i>Problem → Architecture → Result</i></sub>

**Problem** — Upload portals (government, job, exam, KYC) reject files for narrow, mechanical reasons. Generic converters require uploading personal photos and ID documents to a third-party server.

**Constraints** — No backend, no accounts, no uploads: every step of crop, resize, compress, and format conversion had to run entirely on-device.

**Solution** — A bare React Native + TypeScript app (native image modules, not Expo) that takes a photo and a portal's stated requirements and produces a file guaranteed to match.

**Architecture** — Feature-based folders, not layered. A UI-free `imageProcessing` service holds the crop-rectangle math and JPEG quality binary search as pure functions — testable in Jest, no simulator required.

**Trade-offs** — Automatic center-crop instead of an interactive crop UI, to avoid gesture-handling dependencies. PDF support intentionally left out.

**Result** — A working offline-first pipeline with an honest *Ready to Upload / Best Effort / Could Not Meet Requirements* status — it never silently claims success when a size budget can't be met.

`React Native` `TypeScript` `Jest` `On-Device Image Processing`
